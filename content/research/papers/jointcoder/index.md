病历里已经写出疾病或手术名称，并不意味着直接查词典就能完成编码。术语可能不规范，手术名称可能遗漏伴随操作，还需要区分主要与次要项目，核对文本是否支持候选。

JointCoder 将中文疾病和操作编码拆成多个阶段，由不同任务模型分别处理，再结合规则检索与代码映射。作者用真实中文住院记录评估这套流程。

## 一、研究任务与数据边界

输入是一份包含出院诊断、手术名称、手术记录和病程等字段的电子病历。输出有两组有序结果，疾病使用 ICD-10，操作使用 ICD-9-CM-3，主要诊断或操作排在前面。

论文数据来自一家中国医院，以心内科相关住院为主，共 6,747 条记录，由专业编码员按规范标注。模型不仅读取自由文本，还能利用明确的诊断和手术字段。它与只给英文出院小结的 MIMIC 任务，在语言、输入信息、编码细则和数据分布上都不同。

因此，后文的高 F1 只能放在本文任务中解释，不能直接与 MIMIC 模型的分数排名。

## 二、阶段之间传递什么

“智能体”在这里指面向具体子任务微调并按流程调用的模型。系统使用七个本地 Qwen3-1.7B 模型实例，整体分为六个阶段，并非七个模型对所有问题自由讨论。

| 阶段 | 接收内容 | 产生结果 |
| --- | --- | --- |
| 术语标准化 | 诊断或手术字段及完整病历 | 规范化的疾病或操作名称 |
| 候选挖掘 | 手术候选及完整病历 | 从其他记录中补充的操作候选 |
| 重要性排序 | 候选集合及上下文 | 主要与次要项目的有序列表 |
| 伴随编码扩展 | 主要操作和规则索引 | 规范要求补充的操作候选 |
| 证据校验 | 扩展列表及病历 | 删除误报、修正错误并补充遗漏后的列表 |
| 代码映射 | 已核实的标准名称 | 对应标准编码 |

疾病分支使用其中部分阶段，操作分支走完整流程。论文报告，出院诊断字段对疾病覆盖较完整，而手术名称字段经常缺少辅助操作，因此为操作增加候选挖掘。

## 三、为什么排序和校验不能省略

操作分支的伴随编码规则依赖主要操作，先排序才能确定检索依据。作者用 Elasticsearch 建立 ICD-9-CM-3 的 Code Also 规则索引，检索需要另行编码的伴随操作，例如血管或支架数量相关项目。

检索返回的内容仍需回到病历核实。规则说明某些条件下需要补充什么，不能直接证明这份病历满足条件。校验阶段据此删除过度编码、纠正错误名称，并检查漏项，再进入代码映射。

这里至少有三种不同错误。标准化错误会把术语映射到错误概念，候选遗漏会让后续根本看不到某项操作，规则扩展过多则会引入不适用的候选。分阶段设计让这些错误有机会分别检查，也会产生上游错误传递的问题。

## 四、比较设置与主要结果

数据按 9:1 划分训练与测试。论文模型训练 5 轮，最大学习输入为 8,192 token，实验服务器使用八张 RTX 4090。对照包括提示式大模型、监督微调和另一套多智能体编码方法。下表摘取原文表 1 的 F1，保留 0—1 单位。

| 方法 | 疾病 F1 | 操作 F1 |
| --- | ---: | ---: |
| 监督微调 Qwen3-1.7B | 0.8252 | 0.7840 |
| 监督微调 Qwen3-14B | 0.8599 | 0.7954 |
| JointCoder，Qwen3-1.7B | 0.9094 | 0.8615 |

这里沿用原表 F1 名称，不能擅自改成 Micro-F1 或 Macro-F1。结果支持在本文数据上，任务分解与专门训练有助于编码。但七个分工模型构成的系统与一个单模型的训练成本、总参数存储和调用次数不同，不能仅按单个模型的 1.7B 推断整体资源更省。

附录操作消融中，移除标准化后 F1 为 0.2594，移除 Code Also 为 0.6047，移除校验为 0.5003。疾病分支的下降相对较小。这些对照说明操作流程尤其依赖术语和规则处理，不能将全部收益笼统归结为“多智能体更强”。[原文表 1 与附录消融](https://aclanthology.org/2026.acl-demo.26.pdf)

## 五、系统成本与证据范围

论文报告，直接提供结构化文本时平均每条记录处理约 1.8 秒；输入 PDF 时约 15—21 秒，OCR 占据约九成时间。这些是作者环境下的端到端统计，部署时应分别测量文档解析、模型调用、规则检索和映射，不能只比较语言模型生成速度。

结果还受单医院、心内科和中文场景限制。论文说明了训练测试比例，但读者复核时仍需确认患者级隔离、阶段训练材料和提示版本，单有比例不等于划分细节完整。模型也可能生成无依据候选，分阶段校验只能作为降低错误的机制，不能代替独立验证。

这项工作值得借鉴的是把编码员的实际步骤映射为明确的数据接口。各阶段输出可检查，比只得到一串最终编码更容易定位错误；是否改善人工复核效率，还需要实际工作流中的评价。
