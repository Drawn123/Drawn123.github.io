# 内容与维护约定

## 栏目、标签与专题

内容栏目由 `config/_default/params.toml` 的 `mainSections` 配置。文章通过所属顶层目录的 cascade 规则自动继承分类，不再手填 categories；总结、问答是写作形式，不另设一级分类。

栏目决定文章主要放在哪里，标签表达知识点，系列表达连续阅读顺序，专题串联跨栏目的文章。每篇文章只保存一份，算法题解不会因为同时涉及图论和动态规划而复制两份。

目录名统一使用小写英文和连字符；现有中文课程文章文件夹保留，避免无意义迁移。分类使用稳定英文 ID 作为内部名称，分类页显示中文标题。旧分类地址通过别名继续访问；旧“总结”分类直接进入原模板汇总。

新增科目时建立 `content/notes/<subject>/_index.md`，填写 `title`、`description`、`weight`。

新增顶层模块时，在 `mainSections` 中加入目录名，设置模块 `_index.md` 的分类 cascade，并建立 `content/categories/<模块ID>/_index.md`。模块名称、短名称、英文标记和介绍分别填写在模块 `_index.md` 的 `title`、`linkTitle`、`label`、`description` 中；分类详情的介绍也从这里读取，不另维护一份。模块下新增科目或文章会自动继承，无需重复配置分类。构建检查会核对每篇文章是否只有一个、且与所属模块一致的分类。

已有标签暂时兼容原命名。新增标签先检索是否已有同义词。二分查找已合并到二分，旧标签地址有跳转。平台放 `platform` 数组，已填写的题号统一使用 `CF1063B`、`ABC477E`、`P1314` 等格式；缺失信息不猜填。

## 平台与知识点怎么填写、怎么使用

文章开头两个 `---` 之间就是 Front Matter（元数据）。以题解为例：

```yaml
knowledge_id: "solution-abc-287e"
platform:
  - "AtCoder"
problem_id: "ABC287E"
tags:
  - "数据结构 | Data Structure"
  - "字典树 | Trie"
```

- `platform` 是做题网站的名称，看正文中的题目链接确认：`atcoder.jp` 对应 `AtCoder`，`codeforces.com` 对应 `Codeforces`，洛谷题目使用 `洛谷`。沿用站内已有写法，避免把 `AtCoder` 和 `atcoder` 写成两个平台。比赛名称不是平台；只有比赛信息、无法确认做题网站时暂时留空。确实有多个平台的题目链接时才填写多个值。
- `problem_id` 从题目页面确认，例如 AtCoder ABC287 的 E 题写 `ABC287E`、Codeforces 1063B 写 `CF1063B`、洛谷 P1314 写 `P1314`。正文仍保留题目链接；平台名称本身不会自动生成题目地址。
- `tags` 表达知识点，先查已有标签再复用。它们可以点击进入标签文章页，也可以在搜索页的“知识点 / 标签”中筛选。
- `knowledge_id` 是自己为文章指定的全站唯一标识，无需到平台查找。它用于 `knowledge:` 正文链接、`prerequisites` 和 `related_ids`，不是知识点名称，也不是题号。

查找已有字段可运行：

```powershell
rg -n -A 3 '^platform:' content/algorithm/solutions
rg -n -A 6 '^tags:' content
rg -n '^knowledge_id:' content
```

搜索页支持“内容方向 + 做题平台 + 知识点 / 标签 + 关键词”同时筛选，不输入关键词也会显示符合条件的文章。不同条件取交集，例如选 `AtCoder` 和 `字典树 | Trie` 只显示同时满足两项的文章。选项自动收集自已发布文章的元数据，新增平台或标签无需修改前端配置；草稿不会出现在正式构建的选项中。未填平台的文章仍在“全部平台”中，但不会命中某个具体平台。

文章顶部的平台可以点击，直接进入该平台的筛选结果。筛选条件写入搜索页 URL，复制链接后可以保留方向、平台、知识点与关键词；“清除筛选”恢复全部文章。搜索结果同时展示平台、题号和标签，并按每页 10 篇分页。关键词也支持查找 `knowledge_id`，便于确认关联文章。

## 系列阅读

科目 `_index.md` 可设置：

```yaml
learning_series: true
```

同一系列中的文章设置：

```yaml
series_id: "data-structure"
series_order: 1
weight: 10
```

`series_order` 决定系列列表与上一篇/下一篇。`weight` 用于知识树排序，建议取系列序号的十倍。未加入系列的文章不生成跨科目的前后导航。栏目本身用 `weight` 决定入口排序。

## 文章之间如何关联

保留普通外部链接。引用自己博客中的文章时使用稳定标识：

```markdown
先阅读 [最近公共祖先](knowledge:algorithm-lca)。
```

构建时会解析目标文章的真实网址，保留文字、外链样式和可选 `#锚点`。目标不存在或标识重复会使构建失败，避免静默发布坏链接。标识不会因文件改名或移动而变化。`knowledge:` 是本项目提供的扩展，普通 Markdown 编辑器不一定支持点击预览。

系统性关系写在 Front Matter 中：

```yaml
prerequisites:
  - "algorithm-lca"
related_ids:
  - "algorithm-template"
```

页面分别显示“建议先读”和“延伸阅读”；目标文章会自动显示反向引用。正文生成的真实站内链接也会用于反向引用。示例见 `ABC479E`、LCA 与模板汇总，不会基于标题关键词批量猜测知识关系。

标识可在文章 Front Matter 中查找；新增关联前可搜索：

```powershell
rg knowledge_id content
```

## 旧网址

多数已有文章保留原公开地址。按用户确认，算法学习笔记的目录及四个公开地址已统一修正为 `/algorithm/learning-notes/…/`，不为拼写错误的路径保留跳转；数据结构绪论的同类历史错拼别名也已删除。`docs/url-baseline.json` 同步记录这次明确授权的地址调整。

网络赛 C 的历史路径 `/algorithm/solutions/graph-theory/2026online1-c/` 仍保留跳转。

必须换公开地址时，在新页面填写 `aliases` 保留旧路径，同时更新站内引用。GitHub Pages 上的 Hugo 别名是静态跳转页，不等同于服务端 301。

`docs/url-baseline.json` 是保护清单，不要为让检查通过而删除失效路径。新增页面发布后可补充清单；移动、删除、拆分页面时检查旧路径与标题锚点。

## 页面与构建

首页只显示已有文章的模块，内容分类展示全部配置的栏目和子目录，文章总览按时间列出文章。新模块加入 `mainSections` 后，会进入聚合、搜索与归档；子科目无需重复配置。模板通过 `drawn/modules.html` 读取同一份栏目列表，栏目标题和介绍直接读取各自的 `_index.md`。

首页标题默认使用站点名称，可在 `content/_index.md` 设置 `title`、`description` 或正文。最近更新的首次显示数量与每次加载数量共用 `homepage.recentPageSize`，前端从生成页面读取这个值。首页常用入口仍通过 `data/featured.toml` 选择。

文章发布前需设置 `draft: false`。`draft: true` 只在本地使用 `hugo server -D` 时显示，不会随正式部署发布。

各分类详情页直接嵌入所属模块的知识树，不再要求先点击“进入知识目录”。分类页与模块页使用同一个目录组件，文件夹默认全部收起，只显示按优先级排序的最外层目录；点击文件夹名称或箭头才展开下一层，不会自动展开更深层。文章名称仍直接打开正文；新文章会自动进入目录。

右侧默认显示常用标签，原生展开控件能显示其余标签；全部标签页支持搜索与排序。手机通过菜单或首页链接访问全部标签，不依赖右侧栏。

`custom.scss` 中各层按原有顺序加载，最后的 `content.scss` 负责本次内容发现与触摸优化。不要在旧文件尾部不断添加相互覆盖的规则。

构建命令与运行检查见根目录 README。检查脚本只使用 Python 标准库。重新检查时应使用空目录或 `--cleanDestinationDir`，避免旧生成文件掩盖失效链接。

## 背景与互动动效

星空、流星、点击星芒、光标跟随和鲸鱼的移动统一在 `assets/js/drawn-atmosphere.js` 中；两只鲸鱼与三层海浪的形状在 `layouts/_partials/drawn/ocean.html`，配色、摆尾、鳍与喷水样式在 `assets/scss/drawn/atmosphere.scss`。鲸鱼按面朝方向游动，完全离开屏幕后才从另一侧进入。首页模块卡片、常用入口和文章卡片共享主题底色，避免两排卡片出现不同灰色。

浅色与暗色各有星空、点击粒子、海浪和鲸鱼的配色。手机缩小鲸鱼，降低星点数量、画布分辨率和帧率；后台暂停绘制，减少动态效果设置下保留静态星空和鲸鱼。画布不拦截点击，输入控件不触发粒子，触屏滑动不触发点击动画。精细指针设备有柔光圆环跟随，保留系统光标；触屏不显示跟随光标。

鲸鱼整体透明度在桌面浅色 / 暗色下分别为 0.56 / 0.62，手机为 0.5 / 0.56，减轻对底部文字的遮挡。流星在桌面每 3–5.5 秒出现一轮，偶尔成对；手机为 4–6.5 秒，同时数量分别限制为 3 / 2。

鼠标按下即出现星芒，站内跳转通过临时 `sessionStorage` 记录在目标页续播，不取消或延迟链接跳转。新标签页、站外链接、下载与键盘导航保留原行为；存储不可用时仍可正常访问。点击续播不超过 0.9 秒，记录只匹配目标路径并在读取后清除。
